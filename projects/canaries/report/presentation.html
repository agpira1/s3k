My part of the canaries project

Oliver Marcusson

FeatureFileKey parts
1 Memory layout: where each process lives, trap handler at a fixed address, stack left unmapped default.ld, app0.ld, monitor.ld, vuln.ld
  • .trap section at 0x80037000, holding .trap.text
  • __stack_size = 0: the stack isn't part of the image
  • __stack_pointer = 0x80040000: the top of the unmapped stack
2 Helper library over the kernel API, plus canary seeding utils.c, utils.h
3 Vulnerable program with a buffer overflow vuln/main.c
  • greet: reads into char name[64] with alt_gets, which has no bounds check
  • win: the target the exploit jumps to
4 Exploit that overwrites the return address exploiting/exploit.py
  • find_saved_ra_offset: reads the ra offset from greet's prologue
  • find_return_site: the return address into main
  • build_payload, check_payload: build the payload and reject bad bytes
5 Boot: gives the monitor and vuln memory, time and a socket, and gives the monitor control over vuln app0/main.c
  • Grants made in increasing address order: monitor first, then vuln
  • Socket pair on GUARD_CHAN with S3K_IPC_NOYIELD
  • Memory cap over vuln's stack given to the monitor (MON_CAP_STACK_MEM)
  • s3k_mk_monitor caps [1,2) and [2,3): start the monitor and let it control vuln
6 Monitor startup and message loop: suspend vuln, handle the message, resume monitor/main.c
  • vuln_start: sets vuln's trap PC and trap SP (TPC, TSP), then resumes it
  • dispatch: MSG_GUARD_PUSH, MSG_GUARD_POP, MSG_FAULT
  • Loop: s3k_sock_recv → s3k_mon_suspend → dispatch → s3k_mon_resume
7 vuln trap handler: sends each fault to the monitor vuln/trap.c
  • trap_handler: sends ECAUSE, EVAL and EPC with s3k_sock_sendrecv
  • The monitor resuming vuln counts as the reply (the call returns S3K_ERR_SUSPENDED)
  • no_instrument_function: the frame hooks don't run inside the trap
8 Fault handling: decides whether it's an attack, a crash or a normal stack access monitor/faults.c
  • fault_handle: classifies the fault
  • Attack: a fetch from the stack, or an access that hits a guard (found with guard_find)
  • Stop: a non-access fault, an address outside the stack (in_stack), or the same fault twice
  • Otherwise window_map, then resume
